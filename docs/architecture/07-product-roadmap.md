# Domiq — Product Roadmap (рост по аудиториям)

Каждая фаза = аудитория. Архитектурное правило роста: новая фаза
ВКЛЮЧАЕТ и УГЛУБЛЯЕТ модули, но не должна требовать переписывания
ядра. Если фаза N+1 требует переписать модуль фазы N — это дефект
границ, фиксируется как ADR и чинится до начала фазы.

---

## Фаза P1 — Частный собственник, 2–3 квартиры ("убийца Excel")

**Пользователь:** сам себе и владелец, и бухгалтер. Один аккаунт-владелец,
арендаторы — гости со ссылкой/логином. Ценность: перестать вести Excel
и переписку "скинь показания" в мессенджере.

**Модули и глубина:**

| Модуль | Глубина в P1 |
|---|---|
| Identity | владелец + арендатор, без ролей и команд |
| Properties | квартира как объект; без зданий/этажей/юрлиц |
| Tenancy | один жилец на квартиру, период, условия; без сложных договоров |
| Metering | ручной ввод показаний (владельцем ИЛИ арендатором), история |
| Tariffs | тариф с версиями/датами действия — сразу правильно, это ядро расчёта |
| Billing | начисление за период = тариф × потребление + фикс. платежи |
| Payments | ручная отметка "оплачено", сверка, статус для арендатора |
| Notifications | email/telegram: "счёт выставлен", "напоминание", "просрочка" |

**Сознательно НЕ делаем:** онлайн-платежи, документы, заявки на ремонт,
аналитику, мультивалютность, команды пользователей.

**Definition of done фазы:** собственник с 3 квартирами закрывает месяц
(показания → начисления → счета → статусы) без Excel за 15 минут.

---

## Фаза P2 — Инвестор, до ~10 объектов

**Пользователь:** тот же человек, но объектов больше, появляется вопрос
"а выгодно ли это" и текучка арендаторов.

**Что углубляется (без переписывания):**

| Модуль | Дельта P2 |
|---|---|
| Properties | группировка объектов, портфель |
| Tenancy | смена арендаторов, история заселений, депозиты |
| Payments | загрузка банковской выписки, полуавтоматическая сверка |
| Billing | задолженность накопительно, пени (опционально) |
| **Analytics — ВКЛЮЧАЕТСЯ** | доходность по объекту, occupancy rate, просрочки |
| **Documents — ВКЛЮЧАЕТСЯ (минимум)** | договор/акт как файл, привязанный к Tenancy |

**Архитектурная проверка фазы:** Analytics строится ТОЛЬКО на Query
Services и событиях других модулей. Если для отчёта пришлось лезть
в чужие таблицы — граница спроектирована неверно.

---

## Фаза P3 — УК, апарт-отели, девелоперы

**Пользователь:** уже организация. Появляются роли, процессы, объёмы.

**Что углубляется / включается:**

| Модуль | Дельта P3 |
|---|---|
| Identity | организации, роли (бухгалтер, техник, менеджер), команды |
| Properties | здания, подъезды, нежилые помещения, общедомовые счётчики |
| Metering | импорт показаний (CSV/API), общедомовое распределение |
| Billing | массовое выставление, произвольные периоды, юрлица |
| Payments | платёжные шлюзы (онлайн-оплата арендатором) |
| **Maintenance — ВКЛЮЧАЕТСЯ** | заявки на ремонт, статусы, исполнители |
| **Automation — ВКЛЮЧАЕТСЯ** | правила: автосчёт, автонапоминания, эскалации |
| Documents | шаблоны, генерация договоров |

**Архитектурная проверка фазы:** Maintenance и Automation добавляются
как новые модули, подписанные на существующие события
(InvoiceIssued, PaymentOverdue, TenancyEnded) — ядро P1 не меняется.

---

## Фаза P4 — Экосистема (горизонт, не обязательство)

Finance (полноценный учёт), AI (прогноз потребления, аномалии
показаний, ассистент), публичный API для интеграций, marketplace
self-hosted-плагинов. Проектируется только когда P3 живёт в проде.

---

## Как этим пользоваться при проектировании (связь с brief)

1. В спецификации каждого модуля (фаза 1 брифа) раздел
   "Отложено (задел)" размечается тегами P2/P3/P4 — не просто
   "потом", а в какой фазе роста включится.
2. Событийные контракты P1 проектируются с оглядкой на подписчиков
   P2–P3: Analytics и Automation должны смочь построиться на событиях,
   которые Billing/Payments публикуют с первого дня.
3. Границы модулей проверяются вопросом: "переживёт ли эта граница
   P3 без переписывания?" — но реализация всегда по глубине текущей фазы.
4. Между фазами — ретроспектива (фаза 5 брифа): какие решения P1
   мешают P2, ADR на исправление ДО начала новой фазы.
