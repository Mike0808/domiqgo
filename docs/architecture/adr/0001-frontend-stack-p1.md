# ADR-0001: Фронтенд-стек P1 — server-rendered (Django templates + HTMX)

**Статус:** accepted
**Дата:** 2026-07-28
**Фаза роадмапа:** P1

## Контекст

Domiq P1 обслуживает частного собственника с 2–3 квартирами и его
арендаторов. UI фазы P1 — формы и таблицы: ввод показаний, тарифы,
начисления, статусы оплаты. Разработчик — один, профиль backend/infra.
Продукт self-hosted: каждый лишний компонент — это сложность деплоя
у конечного пользователя.

Рассматривались:
1. Django templates + HTMX + Alpine.js (server-rendered)
2. React SPA + DRF API
3. Django templates без JS вообще

## Решение

Вариант 1: Django templates + HTMX + Alpine.js.

При этом внутренняя структура — API-first: views НЕ содержат логику
и НЕ трогают ORM напрямую, а вызывают команды/запросы application
layer модулей. View — тонкий адаптер "HTTP → команда → шаблон".

## Обоснование

- UI P1 (CRUD, формы, таблицы, статусы) не требует клиентского
  состояния — сильные стороны SPA не задействуются, а цена
  (сборка фронта, API-слой, синхронизация состояния, второй
  контейнер) платится полностью.
- Скорость соло-разработки: одна кодовая база, одна модель
  деплоя, фича за вечер вместо недели.
- Self-hosted: docker-compose проще на один сервис — важно для
  аудитории, разворачивающей продукт самостоятельно.
- Вариант 3 отвергнут: без HTMX инлайн-обновления (отметить
  оплату, добавить показание без перезагрузки) деградируют UX
  до уровня, проигрывающего Excel.
- Вариант 2 отвергнут ДЛЯ P1, но не навсегда — см. триггеры.

## Что решение НЕ блокирует

Так как views вызывают application layer, добавление DRF/API
поверх тех же команд и запросов — механическая работа.
React-фронтенд P2+ строится на этом API без переписывания
бизнес-логики. Это прямое следствие правила
"domain и application не знают о способе доставки".

## Триггеры пересмотра

Пересмотреть (новый ADR), когда наступит любое из:
- первый экран, который в HTMX делать заметно больнее, чем в React
  (кандидаты: дашборд Analytics P2 с интерактивными графиками);
- потребность в мобильном приложении арендатора;
- появление фронтенд-контрибьюторов в open source сообществе.

## Последствия

- (+) минимальная сложность P1, быстрый выход к DoD фазы
- (+) деплой одним сервисом
- (−) при пересмотре придётся написать API-слой (но не логику)
- (−) HTMX-паттерны менее знакомы React-разработчикам из сообщества
